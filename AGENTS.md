# AGENTS.md

Инструкции для AI-агентов (Claude Code, Codex, Cursor, pi и др.), работающих с кодом этого репозитория.

> **Scope:** файл настраивает агентов, которые работают над репозиторием `stalexsm/skills` — добавляют и правят скиллы. Копировать его в другие проекты или в глобальную конфигурацию не нужно: переиспользуемая часть этого репо — скиллы в `skills/`, а не этот файл.

## Обзор репозитория

Коллекция agent skills, устанавливаемых через skills CLI:

```bash
npx skills add stalexsm/skills
```

Скилл — это папка с `SKILL.md`: инструкциями, которые агент подгружает, только когда задача совпадает с описанием. Формат — стандарт [Agent Skills](https://agentskills.io).

## Структура

```text
skills/                  # скиллы: skills/<имя>/SKILL.md
└── rsql/                # SQL через rsql CLI
    └── SKILL.md
README.md                # публичное описание и инструкция установки
AGENTS.md                # этот файл
LICENSE                  # MIT
```

Каталог `skills/` сканируется skills CLI автоматически на глубину до 3 уровней (допустимы категории: `skills/<категория>/<имя>/SKILL.md`). Регистрировать скилл нигде не нужно: добавили папку со `SKILL.md` — скилл стал устанавливаемым после пуша.

## Текущие скиллы

| Скилл | Назначение |
| --- | --- |
| `rsql` | SQL к 25+ источникам через rsql CLI: PostgreSQL, MySQL, SQLite, DuckDB, ClickHouse, SQL Server, Snowflake, а также файлы CSV/Parquet/JSON/Excel на диске, S3 и HTTP |

Если задача в этом репозитории совпадает с существующим скиллом, используйте его как источник истины. Например, для любых SQL-запросов к базам и файлам данных читайте `skills/rsql/SKILL.md` и следуйте ему (one-shot паттерн, проверка `Error:` в выводе, чистый вывод через `--footer false --timer false`).

Перед добавлением нового скилла проверьте, что он не дублирует существующий и не пересекается с ним по триггерам в `description`. Расширить существующий скилл обычно лучше, чем заводить близнеца.

## Создание нового скилла

1. Создайте `skills/<имя>/SKILL.md`. Имя папки и `name` из frontmatter должны совпадать.
2. Frontmatter:
   - `name` — kebab-case: строчные буквы, цифры, дефисы; до 64 символов; без ведущих, хвостовых и двойных дефисов.
   - `description` — до 1024 символов, формат «что делает + когда применять». По нему модель решает, загружать ли скилл, поэтому включайте конкретные триггеры — термины, которые пользователь реально упомянет в запросе.
3. Тело `SKILL.md` — инструкции для агента в императиве: когда применять, шаги, правила, критерий завершения. Справочные материалы выносите в `references/`, исполняемые хелперы в `scripts/` и подключайте их относительными путями. Большинство скиллов — чистый markdown; добавляйте файлы только когда они реально нужны.
4. Скилл должен быть самодостаточен внутри своей папки: при установке копируется только она, ссылки наружу от папки не работают.

## Проверка перед пушем

```bash
npx skills add ./skills   # локальная установка из этой папки
npx skills list           # скилл должен появиться в списке
```

Убедитесь, что: новый скилл виден в `skills list`; фронтматтер проходит без предупреждений; инструкции самодостаточны и понятны без знания устройства репозитория; таблица скиллов в `README.md` обновлена.
